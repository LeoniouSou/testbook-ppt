# 对外汉语综合课整册续作（V3）

## 1. 任务契约

把同一位老师、同一套教材的前四课 PPTX 当作已验收课例，学习老师的视觉风格、教学组织、语言点讲解、练习节奏和教学提醒，然后继续完成整本教材剩余课次。

同时做到：

- 保留老师可辨认的风格，不把课件改造成另一套通用模板；
- 允许在不破坏老师风格的前提下优化教学设计、信息密度和版式；
- 尽快交付第一份完整目标课，并在老师审阅时并行准备后续课；
- 把老师返回的修改版 PPTX 直接当作反馈，不要求填写表单或规则标签；
- 默认只向老师交付可编辑教师版 PPTX，逐页包含教学备注，练习包含答案。

所有 PPTX 读取、制作、编辑、渲染和质检都必须调用并遵循已安装的 `Presentations` skill。样例 PPTX 控制风格时，必须使用其 template-following 路径：检查全部源页，复制合适的源页并编辑继承元素，不得仅凭配色、字体或截图重新仿画。

## 2. 必需输入

开始首次建模前，必须具备：

1. 整本教材 PDF；
2. 同一位老师为该教材制作的前四课可编辑 PPTX；
3. 四份 PPTX 与教材前四课对应，并且可以正常打开和读取；
4. 第四课 PPTX 作为语言点讲解和教学提醒的重点参考。

直接从整本教材 PDF 中定位前四课的对应页面。通过“教材原页 ↔ 老师 PPT”对照，判断哪些内容来自教材、哪些是老师的教学加工。不得只看 PPT 猜测老师删改教材的意图。

从文件和样例中自动推断课名、课序、学生水平、课时、拼音策略、英文使用、页面比例、备注方式和答案呈现方式。不得要求用户重新填写能够从材料中得到的信息，也不得要求用户手工整理已学词汇表。

仅在下列信息无法从材料中可靠判断且会改变整册结果时，合并成一次简短提问：

- 文件缺页、课次对应关系不明，或存在多个版本且无法判断老师实际使用哪一版；
- 学生水平或课时在四份样例中明显冲突；
- 多种长期做法互相矛盾，且无法解释为不同页面类型或单课需要。

一次最多询问三个高影响问题。其他低风险不确定项采用最接近样例的做法继续执行。

## 3. 事实、风格与改进的优先级

先按适用范围匹配规则，再在同一设计维度中按证据强度处理冲突：

1. 教材可核验原文、正式教学范围和练习；
2. 用户或老师明确提出的教学与风格要求；
3. 与当前页面类型、知识类型或教学阶段相匹配的高可信条件模式；
4. 四份样例反复出现的稳定默认模式；
5. 第四课在相同适用范围内、且不是 `local` 的语言点讲解、教学提醒和答案处理证据；
6. 当前课的局部需要；
7. 模型提出的优化。

第4课证据仅用于同功能页面的补充或同等级证据的取舍，不得覆盖适用范围更精确的条件模式。

不得把样例 PPT 当作教材事实来源。老师明确修改学生可见内容时，可以按老师要求保留为“教师改编”，但不得冒充教材原文。不得静默更改教材中的疑似错误、拼音争议、人物关系、课文原文或答案。遇到无法核验且可能造成知识错误的学生可见事实时，只暂停受影响页面或课次，并继续处理其他课次。

若四份样例来自不同教师或不同教材系列，禁止混合建模；分别建立模型，或先询问哪一组控制当前整册。

## 4. 两条运行路径

### 4.1 首次建模路径

出现以下任一情况时运行：

- 尚无该老师与该教材的有效模型；
- 前四课样例发生变更；
- 用户指定了新的重点样例；
- 老师或教材系列发生变化。

首次建模完成后，不再为每课重复分析全部样例。

### 4.2 快速生产路径

老师模型有效时，直接加载老师模型、整册课程账本和最近反馈，制作下一批课件。不得重新发起完整访谈、逐页蓝图审批或规则审批。

## 5. 首次建模

### 5.1 并行启动

同时执行以下工作：

1. 检查整本教材 PDF 的目录、课次边界和完整性；
2. 检查四份 PPTX 的全部页面、母版、布局、字体、备注、答案、图片和可编辑结构；
3. 对照前四课教材原页与老师 PPT；
4. 建立整册轻量课次清单；
5. 深度解析第一份尚未完成的目标课；
6. 预解析后续两课的教材范围和素材需求。

不要等整本教材逐页深度解析完毕后才开始第一课。先建立全册边界，再按生产批次深度解析。

### 5.2 学习四类模式

从样例中同时提取以下内容，不得只学习颜色和字体。

#### 视觉系统

- 页面比例、母版、布局和页面骨架；
- 字体、字号层级、行距、段距、边距和留白；
- 主题色、强调色、标题、页码、页眉和页脚；
- 图片、插画、图标、裁切、边框和背景处理；
- 每类页面的信息密度与图文比例；
- 老师提醒、答案或提示在页面和备注中的呈现方式。

#### 教学系统

- 一课的宏观顺序和课时切分；
- 生词、语法、课文、练习分别如何展开；
- 语言点是先举例、先情境还是先规则；
- 新词如何分组、讲解、复现和进入句子；
- 拼音、英文和图片在不同阶段如何出现或撤除；
- 输入、操练、检查和交际活动的节奏；
- 独立、同桌、分组和全班活动如何切换；
- 第四课中完整语言点讲解与教学提醒的结构。

#### 教师执行层

- 每页提醒老师先做什么、如何说、如何示范；
- 学生要做什么、做几轮、用多长时间；
- 常见错误、检查方式、答案和评分标准；
- 哪些提示显示在页面，哪些放在演讲者备注。

#### 单课例外

- 只因某课内容、人物、文化点或时间限制出现的设计；
- 特殊语音页、文化页、临时压缩页或一次性活动；
- 不应复制到后续课程的教材图片、专名、例句或课堂安排。

### 5.3 区分稳定、条件与例外

把观察结果分为：

- `stable`：至少两份样例反复出现且没有实质冲突，或老师明确要求长期采用；
- `conditional`：只在特定页面类型、知识类型或教学阶段出现，但多次机会中保持一致；
- `local`：只出现一次、只适用于某课，或具有明确单课原因。

按“出现机会”判断教学模式。例如，四个课文单元中有三个都采用“带拼音输入 → 去拼音复现 → 角色任务”，应记录为课文条件模式，而不是按它占全部页面的比例计算。

用 `stable / conditional / local` 表示适用方式，用 `high / medium / low` 单独表示证据可信程度，并保存证据页。不得把“只适用于本课”和“证据不足”混为同一字段，也不使用没有可复现量表的百分制评分。

### 5.4 选择控制性参考 PPTX

先为四份样例建立统一页面索引，但不要把它们重建成新的模板注册表。为每一份目标课件单独选择一份控制性参考 PPTX：优先选择能够覆盖该目标课主要页面类型、继承结构完整且可编辑的一份。第四课只在同功能语言点讲解和教师提醒上作为重点证据；标为 `local` 的第四课做法不得覆盖另外三课形成的稳定模式。

每次制作必须从本目标课的控制性参考 PPTX 建立完整源页清单，并把每个输出页映射到一个源页。同一目标 PPTX 的所有 `visualSource` 必须指向这一份控制性参考文件，不得在单个 frame map 中混写多个源 PPTX。复制源页后编辑继承元素，保留母版、布局、字体、间距和视觉结构。不得仅依据内部风格摘要从空白页重建老师风格。若默认控制稿缺少关键页型而另一份样例具备，应先重新评估本课的控制性参考，不得立即硬套或询问老师。

若控制性参考没有完全匹配的页面：

1. 先选择内容结构和教学功能最接近的源页；
2. 缩短内容、拆页或替换继承槽位；
3. 仅在确有必要时做最小、可解释的结构调整；
4. 不得用新增图形盖住品牌元素、页脚或继承占位符；逐个把继承对象标为 `keep / rewrite / replace / delete`，并填充或明确删除空结构占位符；
5. 若整类关键页面都没有可用源页，再把它作为一次高影响问题询问。

### 5.5 保存内部模型

在持久化工作区保存老师与教材专属状态，不写回 Skill 自身：

```text
.tcsl-courseware/
├── sample-manifest.json
├── teacher-course-profile.yaml
├── course-ledger.json
├── learned-preferences.yaml
├── lesson-overrides/
└── production-state.json
```

为所有持久化文件写入 `schema_version`、老师标识、教材标识和更新时间。样例变更或 schema 不兼容时重新建模，不得静默读取结构不明的旧状态。

至少记录：

- 样例文件、哈希、课次和重点样例；
- 稳定视觉规则及证据页；
- 条件性教学模式及触发条件；
- 教师提醒、备注和答案习惯；
- 明确不应复制的单课例外；
- 已完成、待审、草稿和待制作课次；
- 每课累计已学词汇、语法和课堂指令。

这些文件是内部运行状态，默认不交给老师审阅。

为每份目标课件在 `Presentations` skill 指定的临时工作目录中生成并校验：

- `lesson-beat-map.json`：全课教学阶段、目标、用时、互动组织、拼音/英文状态、答案揭示方式和证据；
- `template-frame-map.json`：每个输出页的视觉源页与对象级编辑目标；
- `deviation-log.txt`：相对复制源页的必要偏离及原因；
- `notes-answer-check.json`：逐页备注与逐题答案覆盖状态。

每个输出页同时记录 `contentSources`（教材页码、项目或练习题号）和 `visualSource`（样例文件、源页、母版与布局）。教材来源与视觉来源不得混为一项。

## 6. 整册课程账本

先从整本教材建立轻量 `course-ledger`，记录课序、课名、教材页范围、目标课时和制作状态。生产到某课时再深度提取该课的课文、生词、语法、练习、图片和文化信息。

自动维护：

- `known_items`：此前课程已正式教过的内容；
- `new_items`：当前课正式教学内容；
- `blocked_items`：尚未学且非必要的内容；
- `source_coverage`：教材项目对应到哪一页 PPT；
- `lesson_status`：`queued / drafting / review / accepted / final`。

一课被接受后，把该课正式教学项目自动并入下一课的 `known_items`。不得要求用户逐课提供先修词汇表。

老师回复“继续”时，把当前交付版标记为 `accepted`。老师返回修改版 PPTX 时，除非明确说明“仍是草稿”，把返回文件标记为本课新的 `accepted` 基线；完成差异分析和关键错误检查后标记为 `final`。老师未回复时可以继续准备可重算草稿，但不得把未审课件当作长期偏好证据。

## 7. 第一课校准与并行生产

直接制作第一份尚未完成课次的完整教师版 PPTX；通常是第五课。不要先让老师审批逐页蓝图、风格规则或 YAML。

第一课必须包含：

- 完整学生可见页面；
- 每页教学备注；
- 练习答案或可执行判断标准；
- 与前四课明显一致的视觉语言；
- 在同功能页面上重点参照第4课的语言点讲解方式；
- 必要且克制的教学与版式优化。

交付后只提示：老师可以直接修改 PPTX 并返回。老师审阅期间继续解析并准备后续两课的可重算草稿；不要停止整条生产线。收到修改稿后，先把反馈应用到尚未定稿的后续课，再完成下一批。

## 8. 快速生产路径

每个生产批次执行：

```text
读取批次教材
→ 更新课程账本与先修边界
→ 匹配老师的稳定风格和条件模式
→ 生成并检查全课 lesson-beat-map
→ 为每页选择并复制控制性参考源页
→ 生成学生页面、逐页备注和答案
→ 内容预检
→ 导出并逐页渲染
→ 视觉、备注和文件质检
→ 最多两轮自动定向修复
→ 基于最终文件重新渲染并检查全稿
→ 交付 PPTX
```

采用滚动放量：

1. 首次交付 1 课完整成品；
2. 首课仅有局部修改时，下一批制作 2 课；
3. 风格和教学结构稳定后，下一批制作 4 课；
4. 稳态后按一个教学单元或 6–8 课生产；
5. 出现影响整课的结构性修改时，下一批暂时缩回 1–2 课。

某一课遇到阻塞时，只暂停该课和依赖它的内容；继续处理能够独立完成的其他课次。不得因一个拼音疑点或一页扫描问题停止整册任务。

## 9. 教学与页面规则

把下列要求视为红线，而不是固定模板：

- 忠于教材正式范围，明确区分教材原文与补充内容；
- 按“已知 → 新知 → 组合 → 使用”控制先修边界；
- 不使用未教内容作为练习答案的前提；
- 每个核心目标具备足够的输入、操练和检查；
- 拼音、英文和答案的使用在同一课及整册中一致；
- 图片承担语义或课堂任务功能，不使用误导或低清素材；
- 页面密度和活动数量服从实际课时；
- 所有关键内容在教室投影中可读；
- 所有文字、形状、表格和图片尽量保持可编辑。

不要强制套用固定的十三种页面类型、每词固定页数、每个知识点完整五级练习或每课固定页数。优先继承老师在四份样例中已经验证的页面类型和节奏，并根据本课内容与时间选择必要环节。

允许优化：

- 缩短过密文字、拆分超载页面；
- 改善对齐、留白、图片裁切和视觉层级；
- 补足缺失的练习、答案或教师提示；
- 调整不利于理解的教学顺序；
- 在备注中说明必要的教学动作和常见错误。

优化后仍必须让老师一眼看出课件属于同一套系列。不得引入与样例不一致的通用卡片墙、仪表盘式布局或另一套品牌视觉。

## 10. 逐页备注与答案

为每一页写教师可执行备注。封面、过渡页和结束页可以简短，但不得留空。根据页面需要包含：

- 本页目标和课时位置；
- 建议用时；
- 讲解顺序；
- 教师话术、动作、指图、板书或示范；
- 学生任务、轮次和组织方式；
- 常见错误和检查方式；
- 练习答案、示例答案或评分标准。

学习前四课现有“如何讲解生词和语法”的教学提醒写法。若样例把提醒放在页面上的教师区，则保持同类页面的做法；若样例主要使用演讲者备注，则优先放入备注。不得为了满足固定字段生成空泛语句。

练习页必须提供准确答案；开放任务必须给出判断标准或示例输出。若样例采用单独答案页，延续该方式，同时在备注中保留完整答案。仅在能够检查并证明导入、编辑和导出后仍保留动画 timing、trigger 与答案出现顺序时，才延续点击揭示；否则改用老师样例中已验证的静态答案页或复制页揭示方案，并在内部偏离记录中说明。

## 11. 从老师修改稿学习

老师返回修改后的 PPTX 时，自动与原交付版比较：

- 页面增加、删除、重排和拆分；
- 学生可见文字、拼音、英文和例句；
- 教学备注、时间、话术和答案；
- 图片替换、裁切、布局、字号和强调方式；
- 练习类型、轮次和课堂组织。

把差异自动归入三类：

- `fact_correction`：原文、拼音、答案或知识错误；
- `teacher_preference`：老师稳定的视觉或教学偏好；
- `lesson_override`：只适用于本课的调整。

采用最低干扰的学习规则：

1. 单次视觉或教学偏好修改默认只作用于本页或本课；
2. 删除页面默认视为本课调整，不推断为长期偏好；
3. 同类偏好在两个独立修改实例中重复出现，且能够排除本课内容原因时，自动成为该老师与该教材的条件模式；
4. 老师明确写“以后都这样”时，立即成为该老师与该教材的默认偏好；
5. 经教材或权威来源核验的事实修正不属于个人偏好，应扫描并修复当前批次和后续草稿中的同类错误；老师有意采用的非原文表达则保留为本课“教师改编”；
6. 个人偏好不得扩展到其他老师或教材系列；
7. 每次保留上一版 PPTX 和上一版老师模型，支持回退。

不要要求老师确认每条候选规则。只在下一批交付摘要中列出最多三条已经影响后续课件的长期变化，老师可以直接纠正。

## 12. 仅在必要时打断老师

仅在以下情况暂停并询问：

1. 教材缺失、无法辨认或无法确定课次边界；
2. 教材、官方音频与样例在原文、拼音或答案上冲突，且无法核验；
3. 自动修复后仍有关键内容遗漏、答案无法确定、文件打不开或核心页面不可读；
4. 两条明确长期规则冲突，并会影响多课批量结果；
5. 检查四份样例并重新选择控制稿后，仍完全没有某类关键页面的可用结构。

把同一批次的问题合并为一次、最多三项。只暂停受影响课次，其余工作继续。不要为了颜色、常规布局、图片风格、普通措辞、轻微页数差异或可自动修复的问题询问老师。

## 13. 质检

不使用缺少量表依据的五评估器、百分制权重或 90 分通过线。使用三组二元门槛。

### 13.1 来源与语言门槛

- 教材目标、课文、生词、语法和核心练习无关键遗漏；
- 教材原文、人物、拼音和答案准确；
- 补充例句自然且不冒充教材原文；
- 无未教内容成为答题前提；
- 疑点具有明确证据和处理状态。

### 13.2 教学与备注门槛

- 教学顺序可执行并符合老师模型；
- `lesson-beat-map` 能证明全课的输入、操练、检查和输出节奏完整；
- 相邻页面转换自然，各目标用时之和不超过课时预算；
- 课时预算与页面活动相符；
- 每页具有可用备注；
- 练习具有答案、示例或判断标准；
- 拼音撤除、复现和输出任务前后连贯。

### 13.3 视觉与文件门槛

- 保留控制性参考的 `master → layout → slide` 继承层级、主题部件和可辨认风格，不得扁平化重建；
- 通过 template-following 的 starter/final fidelity 检查，并为所有有意偏离保留内部记录；
- 无意外重叠、溢出、遮挡、断行、空占位符或越界；
- 图片清晰、语义准确、裁切合理且来源可追溯；
- PPTX 可正常打开、编辑和放映；
- 样例包含动画或点击揭示时，比较导入前后的 timing、trigger 和播放顺序；静态渲染不得作为动画保留的证据；
- 重新导入最终 PPTX 后，确认每页备注不含旧课残留，每道练习均有对应答案、示例或判断标准；
- 教学备注与外部来源所需的 `[Sources]` 区块能够并存；
- 所有最终页面均已逐页渲染并在全尺寸下检查。

先对内容蓝图做来源与先修预检；生成 PPTX 后再做渲染、备注、占位符和文件检查。不得在 PPTX 尚未生成时声称已经完成视觉或文件质检。

迭代中只做定向修复并重新检查受影响页面，不得用整份重写掩盖局部错误。最后一次修改后，必须根据最终 PPTX 重新导出并渲染全稿，确认渲染页数等于幻灯片页数，再逐页检查。存在任何关键失败时，不得把受影响课次标记为完成。

## 14. 输出与沟通

默认面向老师只交付：

1. 一课或一个批次的可编辑教师版 PPTX；
2. 一段很短的交付摘要；
3. 仅在确有需要时列出最多三个待确认问题。

不要默认附带逐页蓝图、质检报告、`run_record.json`、`feedback_form.md`、候选规则报告、变更日志或 PPT 差异报告。把这些信息作为内部状态或按需生成。

老师的标准反馈动作是直接修改 PPTX 并返回。聊天中也可以只写：

```text
继续
P12：把这个例句换掉
以后：语法页先出例句，再讲规则
```

不得要求老师书写 `[CRITICAL]`、`[PINYIN]`、规则 ID、反馈类型或严重等级。

## 15. 整册完成条件

只有同时满足以下条件，才能把整本教材标记为完成：

- 所有剩余课次均有最终可编辑教师版 PPTX；
- 每页备注完整，所有练习有答案或判断标准；
- 跨课先修关系、术语、拼音、人名和答案一致；
- 封面、页码、模块标识、字体、颜色和图片处理形成同一系列；
- 已对全册做一次跨课一致性检查；
- 已重新渲染并检查所有最终文件；
- 所有老师已确认的长期修改已经应用到尚未定稿的后续课程；
- 旧版本和老师模型仍可回退。

## 16. 禁止事项

- 不要把首次生产变成完整规则治理平台建设；
- 不要在首课前建设 Supabase、仪表盘、A/B 测试或跨教师全局规则库；
- 不要让老师审批蓝图、YAML、候选规则或自动评分；
- 不要每课重新分析四份样例；
- 不要把不同教师、班级或教材的偏好混入当前模型；
- 不要把单次删页、改图或压缩时间自动升级为长期规则；
- 不要为了遵守固定页面类型而破坏老师已经验证的节奏；
- 不要只学视觉表面而忽略语言点讲解、教学提醒、练习和答案；
- 不要在老师审阅当前批次时停止后续教材解析与可重算草稿准备。
